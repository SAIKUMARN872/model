# Database Migrations

This directory contains everything related to database schema versioning and migration management using **Alembic**.

## Folder Structure

```text
migrations/
├── __init__.py
├── migration.py
├── migration_manager.py
└── README.md
```

## Purpose

The migrations package is responsible for:

- Managing database schema changes
- Creating migration revisions
- Applying database upgrades
- Rolling back database changes
- Viewing migration history
- Managing database version control

## Components

### `__init__.py`

Exports the migration services for easier imports.

### `migration.py`

Contains the core migration service with methods to:

- Upgrade database
- Downgrade database
- Create new revisions
- Display migration history
- Display current database version

### `migration_manager.py`

Provides a higher-level interface for managing Alembic migrations programmatically.

## Prerequisites

Install Alembic:

```bash
pip install alembic
```

Initialize Alembic (first time only):

```bash
alembic init alembic
```

## Create a Migration

Automatically generate a migration based on model changes:

```bash
alembic revision --autogenerate -m "Create users table"
```

Create an empty migration:

```bash
alembic revision -m "Add new feature"
```

## Apply Migrations

Upgrade to the latest version:

```bash
alembic upgrade head
```

Upgrade to a specific revision:

```bash
alembic upgrade <revision_id>
```

## Roll Back Migrations

Rollback one migration:

```bash
alembic downgrade -1
```

Rollback to a specific revision:

```bash
alembic downgrade <revision_id>
```

Rollback all migrations:

```bash
alembic downgrade base
```

## Check Current Version

```bash
alembic current
```

## View Migration History

```bash
alembic history
```

## Programmatic Usage

```python
from app.database.migrations import MigrationService

migration = MigrationService()

migration.upgrade_database()

migration.current()

migration.history()
```

Using the migration manager:

```python
from app.database.migrations.migration_manager import MigrationManager

manager = MigrationManager()

manager.upgrade()

manager.current()

manager.history()
```

## Best Practices

- Never modify an existing migration after it has been deployed.
- Create a new migration for every schema change.
- Review autogenerated migrations before applying them.
- Commit migration files to version control.
- Test upgrades and downgrades in a development environment before production.
- Keep model definitions synchronized with migration files.
- Always back up the database before running migrations in production.

## Dependencies

- Alembic

- PostgreSQL (or another supported SQL database)
- Python 3.11+
